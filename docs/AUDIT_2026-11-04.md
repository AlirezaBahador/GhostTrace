## Fixes on `audit/p0-build-reproducibility`

- Fix incorrect Go module path and internal imports (no change to JSON event schema).
- Update and verify dependency lockfiles using connected GitHub Actions, rather than manufacturing cryptographic hashes.
- Update CI to require formatting, vet, tests, race tests, eBPF ELF checks, API smoke, dashboard build, and `govulncheck`. Standard GitHub runners **do not** attest kernel program loading.
- Require explicit API authentication at CLI startup; keep an explicit unsafe local-development flag for isolated tests. Add regression tests and update systemd examples.
- Upgrade the vulnerable `cilium/ebpf` from v0.17.3 to v0.22.0; this raises the Go toolchain baseline from 1.23 to 1.25. The upgraded agent build is a pending CI gate until verified.

## Next gates and release recommendation

1. **P0**: clean CI after upgraded dependencies, inspect full agent BPF compile and `govulncheck` output. Remove the temporary dependency-bootstrap workflow after lockfiles are committed.
2. **P0**: privileged isolated VM capture of real exec and exit events, verify BPF verifier results, tracepoint links, cleanup, and shutdown.
3. **P1**: quantify output backpressure and loss, improve procfs provenance, tests for corrupted/rotated JSONL and race conditions.
4. **P2**: database migrations, retention, measured API benchmarks, file/network telemetry only after verified semantics.

**Release recommendation: NO-GO.** Source code and unprivileged API work are promising but kernel-level correctness, dependency remediation and repeatable CI must be demonstrated before version `v0.1.0` can be described as verified.
